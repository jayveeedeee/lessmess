# Agent notes: cmd/lessmess

- This directory is the CLI entrypoint; `main.go` is the only file and delegates to `internal/server`, `internal/store`, `internal/docs`, `internal/opencode`, and `internal/registry`.
- `run(args)` parses a subcommand first (`serve`, `validate`, `migrate`, `init`, `docs seed`) and returns an exit code; `main` just calls `os.Exit(run(os.Args[1:]))`. Each subcommand builds its own `flag.FlagSet` and shares a `--dir` flag pointing at the repository root containing `changes/`; every subcommand defaults it to `.` except `serve`, whose empty default selects hub mode.
- `validate` exits 1 only for errors/violations; docs warnings (missing files, freshness lag) print and exit 0.
- The program is `cmd/lessmess` (module `lessmess`), built with `CGO_ENABLED=0 go build -o lessmess ./cmd/lessmess`; `serve`, `validate`, `migrate`, and `docs seed` call `store.MigrateStateDir(dir)` before touching state (a failure there is a non-fatal warning), while `init` bootstraps fresh and does not migrate.
- `serve` and `validate` call `store.MigrateIfNeeded(dir, server.WorktreeChangeRoot(dir))` before the store opens, converting legacy markdown workflow state one-way to the JSON store; a markdown-only repository otherwise fails `store.Open` with `ErrLegacyMarkdown`, and the standalone `migrate` subcommand performs the same conversion on demand (`--dry-run` verifies without writing) with the same resolver. Worktree-backed changes always resolve through `server.WorktreeChangeRoot(dir)`: `validate` additionally calls `st.SetChangeRoot` with it after `store.Open`, so a change whose docs live in its worktree validates at the worktree rather than failing against the main tree.
- The opencode integration is optional: discovery happens once per `serve` process and the single client is shared by every project the instance serves; discovery failures are logged as warnings and the server/docs seeder continue in degraded mode.
- `serve` binds `127.0.0.1` by default and the supported remote/mobile deployment is a trusted LAN or VPN; authentication, TLS, and public-internet exposure are deliberately out of scope, so keep the private default and let an operator explicitly opt into any broader bind.
- `init` reports per-artifact `created`/`merged`/`skipped` actions; `docs seed` accepts `--dry-run` (no writes, no cursor), `--budget N` (summarizer sessions per run, 0 = unlimited), and `--force` (redo every covered directory, ignoring the resume cursor).
- `runDocsSeed` absolutizes `--dir` with `filepath.Abs` before creating opencode sessions (the service rejects a relative session directory with a 500) and reads the effective `session.agent`/`session.model` via `server.SessionDefaults(root)`, so CLI seed sessions match the server's configured defaults.
- `runServe` serves one repository or the whole registry through the same `boot(dir, basePath, publicBase)` closure (per-project `MigrateStateDir`/`MigrateIfNeeded`, `store.Open` + `Watch`, `server.New` with `Base`/`PublicBase` set, shared `SetOpencode`); it returns the handler plus a close func the caller parks in its cleanup list. With `--dir` the project boots at the root with an empty base (legacy root-absolute URLs unchanged); `errors.Is(err, store.ErrNoChanges)` switches to `server.NewSetup(dir, "", callback)`, whose callback re-runs the closure exactly once after bootstrap to hot-swap the full handler in-process — a `changes/` tree missing only its root ledger enters setup mode, while a ledger that exists but fails to parse stays fatal. Without `--dir` it builds `server.NewHub(registry.OpenStore(registry.DefaultPath()), boot, host, port)`, which boots every registered project under `/p/<slug>` with prefix-aware bases and turns boot failures into self-healing `unavailable` slots instead of a fatal exit.
- `queueStale` reads `.lessmess/docs-queue.json` (via `store.StateDirName`) directly, but its schema is owned by `internal/server`; only the `stale` field is consumed here.
