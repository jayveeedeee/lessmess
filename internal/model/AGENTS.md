## Notes for agents

- This package is the workflow data model: `state.go` defines the canonical JSON state under `.lessmess/workflow/`, while `ledger.go`, `table.go`, `taskfile.go`, `serialize.go`, and `templates.go` cover the markdown formats — their parsers and mutators now serve only the one-time markdown-to-JSON migration (`store.MigrateWorkflow`) and tests, while the templates render new prose files at runtime.
- Key files: `model.go` (status vocabularies and `Empty`), `state.go` (JSON workflow state), `table.go` (table and link cells), `ledger.go` (root, change, and container task ledgers), `taskfile.go` (frontmatter), `taskid.go` (dotted task-ID helpers), `docfile.go` (auto sections), `serialize.go` (markdown mutations), `templates.go` (new-file rendering).
- Parsers are strict: pinned columns, valid statuses, and link cells required; literal `|` in a cell is an error, and unknown task-file frontmatter keys are rejected while unknown tasktracker-meta keys are tolerated.
- `state.go` pins the JSON schema: loaders accept only `StateVersion` and reject unknown fields and trailing data; saves are atomic indented JSON. The index deliberately carries no status or update dates (those are authoritative only in each `ChangeState`); tasks are one flat array whose order is priority order per level, with nesting expressed by `Parent` plus dotted IDs; `Validate` checks everything that needs no filesystem access (vocabularies, ID coherence, seq/file agreement, parent and dependency references, cycles).
- Markdown mutation methods (`MoveTask`, `AppendTask`, `AppendRow`, `Update`, `SetOverall`) re-render only the table region, preserving all non-table content byte-for-byte; callers persist through `model.WriteFileAtomic`.
- Tests rely on byte-stable fixtures under `testdata/`; do not regenerate them to match new output.
- `docfile.go` implements the docs-file format: markers are matched as substrings, `ParseDocFile` splits prefix/auto/suffix, and `MergeDoc` rewrites only the auto section (appending after human content when no markers exist) while preserving all bytes outside it; corrupt marker structure yields a typed `*model.Error` so callers can refuse to write. The auto section carries a single freshness meta line (refreshed date, source, tree hash); unknown meta keys are ignored for forward compatibility.
- `TaskStatusOrder` has six entries with `StatusTest` immediately before `StatusDone`; `Valid()` iterates the order, so a new status only needs the constant plus an order placement, and the status-definitions tables in `templates.go`'s scaffolded ledgers must list it in the same position.
- Container task ledgers reuse the change-ledger machinery: `TaskLedger`/`ParseTaskLedger` (`ledger.go`) accept only the minimal headers `- Task: <id> (change <change-id>)` and `- Last updated:`, share the `taskTable` row-mutation core and `TaskColumns` with `ChangeLedger`, and `RenderTaskLedger` (`templates.go`) renders that same minimal format — all of it serves the legacy markdown migration and tests, since JSON state has no per-container ledgers and the served container ledger is a generated view (`store.ContainerLedgerFile`).
- `taskid.go` holds the dotted task-ID helpers (`ParentTaskID`, `ChildTaskID`, `LastTaskSegment`, `TaskIDDepth`, `DottedSegmentsValid`); the rule they encode — the last dotted segment must equal the filename sequence — is positional, and `state.go`'s Validate enforces the same seq/file agreement for JSON tasks, so runtime prose files stay frontmatter-free with identity in the state.
