## Learnings

- Purpose: manages the per-folder AGENTS.md/STRUCTURE.md doc pairs for covered repos — loading `agentsdocs.json`, walking the tree, rendering STRUCTURE.md, seeding content, validating freshness, and refreshing skeletons.
- Core model: `Config` (`config.go`) decides coverage — a missing `agentsdocs.json` makes `LoadConfig` return nil and every consumer no-op; `Walk`/`Dir`/`PostOrder` (`walk.go`) inventory the tree; `Build` (`structure.go`) renders STRUCTURE.md bottom-up so parent rollups quote child purposes.
- Everything is idempotent and merge-safe: writes go through `model.MergeDoc`/`model.WriteFileAtomic`, content outside the tasktracker markers is preserved byte-for-byte, and unchanged trees keep their prior freshness stamp.
- `Seed` (`seed.go`) runs three phases (skeletons, summarization, settle rollups), rewrites the deterministic skeletons every run, tracks only LLM-summarized dirs in the `.lessmess/docs-seed.json` cursor, and resumes from it; its confinement matches the gardener (pre-pass snapshot, no deletions, created `AGENTS.md` must use markers) and rollback may delete an unreviewed newly created file.
- Seed sessions need an absolute repo root and can outlast the service's 30s HTTP cap: `OpenCodeSummarizer` uses one session per dir and `WaitDone` retries transport timeouts until the context expires; the configured agent/model threads through `SessionClient.CreateSessionWith` via `NewOpenCodeSummarizerWith`, with callers injecting the factory (`newSeedSummarizer` in `internal/server/setupseed.go` is the test seam).
- `Seed` supports targeted runs: `SeedOptions.Dirs` restricts summarization, `Force` ignores the cursor, and `MissingDocDirs` lists covered dirs lacking the doc pair — the wizard, CLI, and server `POST /docs/seed` share these plus one cursor, so interrupted or budget-capped runs resume with one call.
- `initAgents` (`init.go`) ends a freshly created root `AGENTS.md` with an empty marker section and appends one to older marker-less copies: without a sanctioned append target, seed and gardener sessions invent their own section and get rolled back by confinement.
- `InitWithOptions` makes docs coverage a bootstrap option: `InitOptions{Config:false}` skips `agentsdocs.json` entirely and `Exclude` applies only when the config is first created — init never modifies an existing config (exclusion edits go through `updateConfigExcludes` in `internal/server`).
- `ValidateDocs` treats structural problems as errors but coverage/freshness gaps and stale references as warnings, so docs lag never blocks a change close-out; `StaleDirs` (`validate.go`) returns the sorted covered dirs whose freshness meta is missing, unparseable, or lags the walked tree hash (computing hash-staleness directly for the refresh union; nil without a config).
- `StaleLearningRefs` (`learnings.go`) lints auto sections for dead references: only backticked, path-shaped spans with a known final extension are candidates (`knownExts` filters out dotted identifiers like `server.New`); resolution is deliberately generous — exact or tail relative path, base-name match anywhere, sibling variants, `.lessmess` state — so only literally-missing paths flag.
- The lint is read-only and warnings-only: `ValidateDocs` emits `learning cites missing path` per flagged ref, deduplicating identical missing paths across directories into one finding with a count and example dir. Example paths inside learnings are lint-checked like real ones, so write examples with unknown-extension tails, dotted identifiers, or no backticks at all.
- `DirDocs` (`readdocs.go`) is the explorer's only docs read path: a placeholder purpose reports empty, a missing STRUCTURE.md reports zero values without error, and corrupt markers are errors — the "placeholder → empty, missing → zero, corrupt → error" contract must stay stable.
- Tests build STRUCTURE.md fixtures as literal marker/meta/table strings, so changes to the rendered format usually require updating `structure_test.go` and `readdocs_test.go` together.
- `internal/docs/assets/` holds the canonical embedded workflow text that `init` merges into target repositories' root `AGENTS.md`; it is drift-pinned against the repo's own `AGENTS.md`.
- `Init` bootstraps the workflow surface in lockstep — the embedded workflow text into `AGENTS.md`, the empty `changes/` tree, `.lessmess/workflow/index.json`, a starter `opencode.json`, and a gitignore block of `.lessmess/*` with `!.lessmess/workflow/` so tooling state stays personal while the JSON workflow state stays committed; update the asset and the generated text together or fresh repos inherit wording that contradicts the spec.
