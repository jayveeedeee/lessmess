## Working in internal/opencode

- Purpose: a thin HTTP client for the opencode background service, covering only the endpoints lessmess needs.
- Key types: `Client` (Basic-auth HTTP wrapper), `APIError` (non-2xx responses), and `Session`; build clients with `New` or `DiscoverClient`, and call methods like `CreateSession`, `ListSessions`, `Prompt`, and `WaitDone`.
- Session and chat requests go through `Client.do`, which sets Basic auth with user `opencode` and unwraps the service's `{"data": ...}` response envelope (`doEnvelope` also returns the cursor for paginated endpoints); the capability and management reads in `management.go` and `lifecycle.go` build their own Basic-auth requests and skip the envelope.
- `Discover` shells out to `opencode2 service status`; the password is read from `~/.config/opencode/service.json` (override the path via `PasswordFromFile`).
- `WaitDone` blocks on the server-side wait endpoint and retries transport timeouts until the caller's context expires; a context error means the session is still busy.
- `TestLiveSmoke` only runs with `TT_LIVE_OPENCODE=1`; all other tests use `httptest` fakes.
- `CreateSessionWith` adds optional `agent` and `model` defaults to the V2 create body; plain `CreateSession` just delegates with empty values. A 400 for an unknown agent/model is returned to the caller — the warn-and-retry-plain fallback lives in `internal/server`'s `spawnSession`, not here.
- `ModelRef` mirrors the V2 `Model.Ref` schema (`providerID` + `id`, plus an optional `variant` lessmess never sets); model IDs may contain slashes, so a stored `providerID/id` string must be split on the first `/` only (`splitModelRef` in `internal/server`).
- `ListAgentsFor`/`ListModelsFor` scope requests with the deep-object `?location[directory]=<dir>` query so agents/providers defined by the served repository's own opencode config are included; they return raw lists — filtering to primary, non-hidden session drivers happens in `internal/server`'s `settingsapi.go`.
- `Session.ParentID` carries the service's `parentID`, populated on task-tool-spawned subagent children and parsed by both `ListSessions` and `GetSession`; it is the authoritative hierarchy signal — `internal/server`'s task-session reconciler and Chat's Agents navigation enumerate a parent's children with `ListChildrenPage` (ascending first page, then cursor) and re-verify `ParentID` on each returned child rather than trusting the query alone.
- Chat runs on dedicated adapters: `ListMessages`/`ListMessagesPage`, `GetMessage`, `GetSessionContext`, `GetSessionDiff`, `ListActiveSessions`, `Interrupt`, `ListPermissions`/`ReplyPermission`, and `ListForms`/`ReplyForm`, with prompts carrying files and skills and controls covering agent, model, command, and skill activation; assistant `text`, `reasoning`, and `tool` content decode to typed parts while `UnknownPart` retains the discriminator and raw JSON, so service-side additions degrade to a safe fallback instead of breaking a transcript.
- Volatile service surface is capability-gated: `LifecycleCapabilities` and `ManagementCapabilities` fetch the service's OpenAPI document and test for the exact method and path (sometimes a body field) — never a version string, and mutating operations are never probed; where published and installed services differ (rename PATCH vs POST, revert clear, inbox delivery, MCP connect) detection selects the compatible route, and every `cap`-taking method returns `ErrCapabilityUnavailable` when the operation is absent.
- Browser-bound responses are projected display-safe at decode time: custom `UnmarshalJSON` implementations normalize enums through `knownEnum` (unknown values collapse to `unknown`) and drop secrets, command lines, raw failure text, credential names, and URL or path detail (integration metadata, MCP failures and resource URIs, permission resource lists become counts), so handlers can serve client types without further redaction.
