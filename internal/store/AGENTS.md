# Agent notes: internal/store

<!-- tasktracker:begin -->
- Purpose: maintains the in-memory model of the repository's workflow — the canonical JSON state under `.lessmess/workflow/` plus the prose tree under `changes/` — watches both for external edits, validates them, and performs safe writes.
- Key types: `Store` (cache plus watcher), `Change` (JSON state plus prose directory, which may live in a worktree), `TaskNode` (one task in a change's tree), `Event` (fs/write notifications), and `Violation` (rule breach); entry points are `Open`, `Reload`, and the mutations of `store.go` and `mutations.go` (`MoveTask`, `CreateTask`, `CreateChange`, `SetChangeStatus`, `SetTaskStatus`).
- Writes are conflict-safe: every mutation re-reads the target state file (`freshState`), applies the change to the fresh content, validates it, and saves atomically via `model.WriteFileAtomic` — external edits are never clobbered, and every state write reloads and notifies listeners. Prose files are only ever created from templates, never rewritten.
- Errors are sentinel-based: unknown IDs return `ErrNotFound`, writes against unparseable state return `ErrInvalid`, absent workflow state is `ErrNoChanges`, un-migrated markdown state is `ErrLegacyMarkdown`, and subtask operations hit `ErrNoContainer`/`ErrContainerExists`. Task sequence numbers are never reused (highest existing at the level + 1); change IDs mint a random five-character lowercase alphanumeric suffix through the injectable `randSuffix` seam (crypto/rand) with a bounded 10-retry collision check over same-date prose directories and index entries (worktree-backed changes have entries but no main-tree directory); `changeIDRe` accepts both suffix formats (legacy `\d+`, new `[a-z0-9]{5}`) permanently — no migration.
- `Watch` uses fsnotify with a 150ms debounce, ignores `.tt-` temp files, and skips attribute-only events (`ev.Op&^ fsnotify.Chmod == 0`) before debouncing — git scans read modified files and macOS reports the atime updates as `CHMOD`, which would otherwise retrigger reloads on every index render. It watches the whole workflow-state subtree plus every prose tree, including worktree-backed directories outside the main tree, re-walks the dir set after every debounced reload so directories created since the last scan (fresh decompose containers included) come under watch without a restart, and converges derived overall statuses after each external-edit reload. Listeners subscribe via `Subscribe`/`Unsubscribe` and receive `fs` and `write` events.
- Docs validation deliberately lives in `internal/docs.ValidateDocs`, not here: the store stays focused on the workflow contract and gains no docs dependency.
- `statedir.go` exports `StateDirName` (`.lessmess`) and `MigrateStateDir`, called at CLI startup before `Open`; it renames a legacy `.tasktracker` dir only when `.lessmess` is absent, so an existing current dir always wins and nothing is merged or deleted.
- Overall status derives from the task tree (`overall.go`): Planned while nothing has started, Blocked when every open task is Blocked, otherwise In progress — a fully complete tree stays In progress because close is user-gated. `syncOverall` reconverges the derived status after every task-level write; user-set `Done`/`Cancelled` (`Derived: false`) are exempt. `SetChangeStatus` writes only the state file, and `SetTaskStatus` demands verification evidence for `Test` (in the request or the task's notes).
- Change creation splits prose from state: `CreateChange` scaffolds into the main `changes/` tree, while `CreateChangeAt` writes prose under a caller-supplied root (worktree-backed changes) and always writes the state file and index entry into the main-tree workflow store. `branch` is recorded verbatim in state and index — informational only, the store never creates a git branch.
- `Open` requires the workflow index file: a repo still holding its root ledger at changes/ledger.md fails with `ErrLegacyMarkdown` (run the migration first), a repo with neither state is `ErrNoChanges` — `errors.Is(err, ErrNoChanges)` is the only sanctioned setup-mode test — and an index that exists but fails to parse is a hard error.
- Doc readers split by kind: `PlanFile` returns the plan prose raw; `TaskFile` resolves identity from the JSON state by change-relative href and returns the body raw (prose files carry no frontmatter); `LedgerFile` and `ContainerLedgerFile` are generated markdown views of the state, the latter accepting the legacy tasks/…/ledger.md href shape. Presentation trims like `dropLeadingH1` happen in the server, so the store never rewrites file content.
- The recursive task tree spans three files: `store.go` holds `buildTree` (constructs `TaskNode`s from the state's flat task array — array order is priority order per level) and `MoveTask` (reorders within a status group at the task's level); `mutations.go` holds `DecomposeTask` (creates only the container prose directory and its `tasks/` subdirectory — the sub plan itself is state, so there is no per-container ledger) and `CreateTask` (numbers children within the governing level); `tree.go` holds the node machinery — `Change.Node`/`WalkTasks` resolve dotted IDs across the whole tree, `scanProse` cross-checks prose against the referenced files (orphans and stray directories feed validation; container dirs may sit empty right after decomposition), and `SubtreeStats`/`AllTaskStats` feed display-only rollups (Test+Done complete, Cancelled out of the denominator, nothing ever written back).
- Validation checks the JSON state and prose tree against numbered rules (`Validate`): valid change directory names (rule 1), required plan prose and tasks dir (rule 2), state/prose agreement — referenced files exist, no orphan files, no stray directories (rule 3), status vocabularies (rule 4), the state schema from `model`'s Validate (rule 5), and index/prose consistency including unresolved worktree-backed entries (rule 6). `CloseOutReady` returns every non-cancelled task at any depth that is not `Test` or `Done`.
