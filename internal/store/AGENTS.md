# Agent notes: internal/store

<!-- tasktracker:begin -->
- Purpose: maintains the in-memory model of the repository `changes/` tree, watches it for external edits, validates it against the AGENTS.md rules, and performs safe writes.
- Key types: `Store` (cache plus watcher), `Change` (one change directory), `Event` (fs/write notifications), and `Violation` (rule breach); entry points are `Open`, `Reload`, and methods like `MoveTask`, `CreateTask`, `CreateChange`, `SetChangeStatus`.
- Writes are conflict-safe: every mutation re-reads the target file, applies the change to fresh on-disk content, and writes atomically via `model.WriteFileAtomic`; external edits are never clobbered.
- Errors are sentinel-based: unknown IDs return `ErrNotFound`, writes against unparseable files return `ErrInvalid`. Task sequence numbers are never reused (highest existing + 1); change IDs mint a random five-character lowercase alphanumeric suffix through the injectable `randSuffix` seam (crypto/rand) with a bounded 10-retry collision check over same-date names in `changes/` and `changes/archive/`, and `changeIDRe` accepts both suffix formats (legacy `\d+`, new `[a-z0-9]{5}`) permanently — no migration.
- `Watch` uses fsnotify with a 150ms debounce, ignores `.tt-` temp files, and skips attribute-only events (`ev.Op&^ fsnotify.Chmod == 0`) before debouncing — git scans read modified files and macOS reports the atime updates as `CHMOD`, which would otherwise retrigger reloads on every index render. Listeners subscribe via `Subscribe`/`Unsubscribe` and receive `fs` and `write` events.
- Docs validation deliberately lives in `internal/docs.ValidateDocs`, not here: the store stays focused on the `changes/` contract and gains no docs dependency.
- `statedir.go` exports `StateDirName` (`.lessmess`) and `MigrateStateDir`, called at CLI startup before `Open`; it renames a legacy `.tasktracker` dir only when `.lessmess` is absent, so an existing current dir always wins and nothing is merged or deleted.
- `CreateChange(title, prefix, branch, date)` writes `branch` verbatim into the root ledger's Branch column (`—` when empty; server callers pass the effective `git.defaultBranch` setting) — informational only, the store never creates a git branch.
- `Open` returns the `ErrNoChanges` sentinel in two setup-mode cases: `changes/` absent and a partial tree where `changes/` exists without a root ledger; a ledger that exists but fails to parse stays a hard error, so `errors.Is(err, ErrNoChanges)` is the only sanctioned setup-mode test.
- Raw change-doc readers keep one shape: `PlanFile` and `LedgerFile` return the file's markdown verbatim (fixed filename, `ErrNotFound` on miss, no parsing), while `TaskFile` parses and path-guards its href argument — presentation trims like `dropLeadingH1` happen in the server, so the store never rewrites file content.
- `tree.go` holds the recursive task tree: `scanTasks` builds a `TaskNode` per task file (href, parent, children, governing ledger), `Change.Node`/`WalkTasks` resolve dotted IDs across the whole tree, `DecomposeTask` creates the container atomically (sentinel refusal when it exists), `CreateTask` numbers children within the parent's container, `MoveTask` writes the task's governing ledger, and `SubtreeStats`/`AllTaskStats` feed display-only rollups (Test+Done complete, Cancelled out of the denominator); `watch.go` rebuilds its watch set so newly created nested directories notify.
- Validation walks the tree per level (`validateTaskTree`/`validateLevel`): every directory under any `tasks/` must be the container of its sibling numbered task file, so stray directories are violations, and `CloseOutReady` returns every non-cancelled task at any depth that is not `Test` or `Done`.
