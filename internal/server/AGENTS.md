## Learnings

- Purpose: the HTTP layer over `store.Store` — HTML pages, JSON endpoints, an SSE stream, opencode session management, a PTY terminal, and the docs refresh queue. Handlers branch on `wantsHTML`/`isHX`/`isJSON` (JSON default); optional integrations are nil-disabled (`s.oc`, `s.docsQ`) — guard and return 503; tests use fixture stores and fake clients (`SpawnCommand`, `SetDocsRunner` injectable). Key files: `server.go` holds `Server` and the route table; `mapping.go` owns `.lessmess/sessions.json`; `docsqueue.go` plus `docssession.go` drive doc gardening; `render.go` owns templates and static assets; `touched.go` extracts covered dirs from tasks' "Files affected".
- Sessions are primed at creation: change sessions get `changePrompt` (a prime failure deletes the session and returns 502 so nothing unbound leaks), scaffold refuses an already-bound session with 409, binding is absolute and applies only to new sessions, and the discussion prompt's step-0 empty state is pinned by tests — prompts reach only sessions created after a change to them.
- The nested task surface lives here: `GET /changes/{id}/tasks/{file...}`, `POST /changes/{id}/expand` (409 when the container exists), `POST /changes/{id}/tasks` with optional `parent`, `?task=` drill-down boards with breadcrumbs, recursive counts via `SubtreeStats`, and close gated on `store.CloseOutReady`.
- Subagent sessions bind at every tree node: `taskTitleRe` matches dotted IDs, `reconcileTaskSessions` (run from `listChangeSessions` only) maps `parentID` children additively and dedup-safe, `bindTaskSession` is the corrective bind with guard order 422 → 409 → 200 idempotent → 201, `SessionEntry` carries optional `task`/`parent` (`omitempty`), and auto-spawn is once per container via `.lessmess/autosession.json` (failed spawn leaves the marker unset).
- The status endpoint `POST /changes/{id}/status` (`lifecycle.go`) delegates to `store.SetChangeStatus` (change ledger + root-ledger row atomically): `Done` → 409 naming `/changes/{id}/close`, `Cancelled`/unknown → 422, same-status calls rewrite both files with today's date. The board's `#overall-status` select reloads from server truth even on failure.
- The index sorts newest-first server-side (date prefix descending, then root-ledger row position descending, then ID ascending; IDs under ten characters sort last) — pinned by `TestIndexNewestFirst`; `statusRank` in `templateFuncs` maps `model.TaskStatusOrder` with `len` as the unknown-status fallback. Client-side sorting persists to localStorage; the server's only job is emitting `data-*` keys, never scraping display text.
- All user-visible markdown renders through the shared goldmark instance in `render.go` (auto heading ids + GFM tables — bare `goldmark.New()` gives neither); plan/ledger detail handlers render an HTML partial vs JSON on `wantsHTML`/`isHX`; `dropLeadingH1` and other presentation trims stay server-side, while TOC, scroll-spy, and `.md` link interception are client-side in `app.js`.
- The explorer is the docs-system UI (`explorer.go`): `/explorer` page, `/explorer/tree` fragment, `/explorer/detail` per-directory pane, `/explorer/chat` root-scoped session mapped to unassigned Discussions; detail re-walks and validates (`.` is root, 503 without docs, 422 uncovered/missing, 404 absent); `docswatch.go` merges debounced fsnotify events into `/events` as kind `docs`, ignoring hidden files, `.tt-` temp files, and attribute-only `CHMOD` (macOS atime from render-time git scans).
- The embedded terminal stays chrome-free: `tuiconfig.go` merges the user's `~/.config/opencode/cli.json` under forced `tabs.enabled=false`/`session.sidebar=hide` into `.lessmess/xdg/opencode/cli.json` (best-effort, fail-open, atomic), `xdgEnv` replaces any inherited `XDG_CONFIG_HOME`, and the task panel beside it is purely client-side.
- Git awareness is read-only in Go: `gitcommit.go` shells out for status preview (`GET /api/git/status`), `POST /api/git/commit` re-checks dirtiness then primes a repo-wide `repoCommitPrompt` session, both flows share the `commitStatus` poller, and `indexView` computes `GitRepo`/`GitDirty` at render time — the actual commit always happens inside an opencode session.
- The gardener runs a whole-tree skeleton refresh then one session per job; confinement requires out-of-marker bytes to equal the pre-pass snapshot, the meta hash to match the walked tree, no snapshot deletions, and markers on any created `AGENTS.md` — violations restore and flag stale. `gardenerPrompt` renders update dirs plus a REVIEW-AND-FIX section for `coveredAncestors` (fix/delete license, reply must account for every removal); manual jobs stay single-section with lint-flagged refs named; learnings are consolidated in place — current-state phrasing, no provenance prefixes, at most 15 per file. `.lessmess/docs-queue.json` holds pending/stale atomically; a missing runner fails a job straight to stale.
- Settings live entirely in this package: `settings.go` owns the stateless layered load/merge (project `lessmess.json`, personal `.lessmess/settings.json`, tri-state fields), `settingsapi.go` serves `/settings` + `/api/settings` and validates agent/model against the live service at save (422; skipped when unreachable — creation itself never validates, it de-escalates on a 400 instead), `settingschange.go` keeps one active per-field discussion via `.lessmess/settings-change.json`, `opendefault.go` reads the served repo's `opencode.json` `default_agent` into the payload (`opencodeDefaultAgent`, present only when declared; missing file/empty key is `absent`, JSONC/non-plain-JSON is `unreadable`, failures degrade to no notice) and serves Align `POST /api/settings/opencode-default-agent` — live validation (422 unknown/empty agent, 503 unreachable; stricter than save), existing key required, only that value rewritten byte-preserving via `model.WriteFileAtomic`, and `settingsFieldValue`'s dotted-path allowlist must extend in lockstep with `EffectiveSettings`. `general.projectName` never stores its default: effective reads (`loadEffectiveSettings`/`effectiveProjectName`) compute the `filepath.Base(repoDir)` fallback (guarded to `lessmess`) at read time, the sources map keeps reporting `default` while unset, and `settingsResponse.defaultProjectName` exposes that folder default to the UI.
- `spawnSessionWithModel` (`settings.go`) de-escalates on a 400 `opencode.APIError` — agent+model → agent-only → model-only → plain, built from whatever is actually configured and always ending in plain so a bad setting never blocks spawning; any other error returns immediately, every dropped piece logs a warning, and `spawnfallback.go` records the outcome (attempted agent/model, winning step, service error) in `.lessmess/spawn-fallback.json` — best-effort write on a de-escalated success, removed whenever the first attempt succeeds, read fail-open so a malformed record never breaks the index; `indexView` renders the board banner from it at render time, the same pattern as `GitDirty`.
- The accent system rolls once: `accent.go` is the only palette source, `ResolveAccent` persists a random pick through `persistAccent` (whole `ui` section — `applySettingsPatch` replaces sections), unknown stored ids fail open to the default without a rewrite, and `ui.accent` validation is offline and always enforced (unlike agent/model). `brandassets.go` serves `/icon.svg`, `/favicon.ico`, and `/apple-touch-icon.png` rendered per accent with accent-id ETags and `no-cache` 304 revalidation; the setup mux mounts the same routes over the no-roll `effectiveAccentColor` read path (no store in setup mode), and `render()` fills `pageData.AccentStyle` and `pageData.ProjectName` centrally through the wired `accent`/`projectName` hooks (both wired in `server.New` and `NewSetup`), so handlers never touch either.
- Setup mode gates solely on `store.ErrNoChanges`: `NewSetup` serves the wizard plus `/api/setup/*` on both muxes (everything else 503/redirect), bootstrap hot-swaps the full handler in-process, prereq probe seams are package-level fakes (only `fail` blocks), onboarding state in `.lessmess/onboarding.json` fails open, and the docs-seed endpoints share one in-flight registry plus the `.lessmess/docs-seed.json` cursor (409 while running, 503 without opencode or coverage).
