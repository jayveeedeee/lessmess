# Agent notes: internal/server

- Purpose: the HTTP layer over `store.Store` — HTML pages, JSON endpoints, an SSE stream, opencode session management, a PTY terminal, and the docs refresh queue.
- Key files: `server.go` holds `Server` and the route table; `mapping.go` owns `.lessmess/sessions.json` (via `store.StateDirName`); `docsqueue.go` plus `docssession.go` drive doc gardening; `render.go` owns templates and static assets.
- Handlers branch on helpers `wantsHTML`, `isHX`, and `isJSON`: JSON is the default, with HTML or htmx partials served when requested.
- Optional integrations are nil-disabled (`s.oc` for opencode, `s.docsQ` for docs); guard handlers and return 503 when they are absent.
- Tests use fixture stores and fake opencode clients or `DocsRunner`s; keep `SpawnCommand` and `SetDocsRunner` injectable.
- (manual) The explorer is the docs-system UI: `explorer.go` serves `/explorer` (page), `/explorer/tree` (htmx fragment), `/explorer/detail` (per-directory detail fragment), and `/explorer/chat` (root-scoped opencode session mapped to the unassigned bucket).
- (2026-09-12-11) `explorerDetail` re-walks the covered tree and locates the requested node with `findExplorerNode` (`"."` is the root); it mirrors `explorerChat`'s validation — `dir` defaults to `.`, 503 when `docsQ` is nil, 422 for uncovered or missing directories, and 404 when the node is absent from the walk.
- (manual) Explorer chat requires both `s.oc` and `s.docsQ`, validates the requested dir via `cfg.Covered`, and returns 503 when either optional subsystem is absent.
- (manual) `docswatch.go` watches covered directories with fsnotify, ignores hidden files and our `.tt-` atomic temp files, debounces ~300ms, and rebuilds its watch set after each quiet period so newly covered dirs are picked up.
- (2026-09-12-7) `closeChange` runs a best-effort docs hook after the status flip and never fails the close; `touched.go` extracts dirs from the first backtick token of each "Files affected" bullet, drops `changes/`, hidden paths, and doc files, then bubbles to the nearest covered ancestor.
- (2026-09-12-7) `.lessmess/docs-queue.json` holds pending and stale in one atomic file; the worker drains immediately, a missing runner fails a job straight to stale, and `POST /docs/refresh` enqueues one "manual" job covering the whole stale set.
- (2026-09-12-7) `docssession.go` does a whole-tree skeleton refresh before one gardener session per job; the confinement check requires out-of-marker bytes to equal the snapshot, the meta hash to match the walked tree hash, no snapshot deletions, and markers on any created `AGENTS.md` — violations restore and flag stale.
- (2026-09-12-8) The explorer keeps the store docs-free: `docswatch.go` lives in this package and merges its debounced events into `/events` as kind `docs`; the explorer page re-fetches `/explorer/tree` on them while board/index JS ignores them.
- (2026-09-12-8) `explorerPrompt` embeds the target dir's STRUCTURE.md and AGENTS.md (missing files become "(not present)") and forbids writes; `POST /explorer/chat` runs the session in the repo root, rejects uncovered/nonexistent dirs, and maps the session to the unassigned Discussions bucket.
- (2026-09-12-9) `POST /docs/refresh` (`docsRefresh` in `docsqueue.go`) enqueues one manual job for the union of `q.staleDirs()` (queue-stale) and `docs.StaleDirs` (hash-stale), deduped and sorted; an empty union returns 200 `nothing to refresh`, and a hash-check error logs and falls back to the queue-stale set rather than failing the request.
- (2026-09-12-10) Change sessions are primed at creation: `createChangeSession` (`mapping.go`) calls `s.oc.Prompt` with `changePrompt(id)` to bind the session to its change and forbid `/changes/scaffold`; a prime failure deletes the session and returns 502 so no unbound session leaks.
- (2026-09-12-10) `POST /changes/scaffold` (`scaffoldChange` in `changesession.go`) refuses a session already mapped to a change via `mapping.changeOf` with 409 and a JSON body naming that change. Unassigned sessions still scaffold and move; unmapped sessions still scaffold and direct-link.
- (2026-09-12-10) Session binding is absolute (no escape hatch) and only applies to newly created sessions — pre-existing sessions are not retro-primed but remain covered by the 409 guard. `changePrompt` lives beside `discussionPrompt` in `changesession.go` even though its only caller is in `mapping.go`, for discoverability.
- (2026-09-12-12) `Server.index` (`server.go`) sorts root-ledger rows newest-first with `changeIDLess`: the `YYYY-MM-DD` prefix compares lexicographically while the unpadded counter compares numerically, so `2026-09-12-9` sorts below `-12`; the HTML page and JSON response share one sort and `TestIndexNewestFirst` covers it.
- (2026-09-12-14) Server state now lives under `.lessmess/` (`sessions.json`, `docs-queue.json`) and `server.New` defensively calls `store.MigrateStateDir` before loading the mapping; rendered output and `render_test.go` assert the `lessmess` brand, and the agent prompt builders contain no app-name mentions (only unchanged marker syntax).
- (2026-09-12-15) The board now renders six columns in `TaskStatusOrder` order (Not started, In progress, Blocked, Test, Done, Cancelled); `server_test.go` and `render_test.go` still hard-code the column count and status ordering, so a vocabulary change requires updating both.
- (2026-09-13-0) `gitcommit.go` adds repo-wide git awareness: `gitStatus` shells out read-only (`rev-parse`, `status --porcelain`, then `diff --numstat HEAD` merged into the porcelain rows plus a `diff --shortstat HEAD` summary, with a `--cached` fallback on a commitless repo) behind `GET /api/git/status`, degrading to `repo:false` instead of erroring when git or a work tree is unavailable.
- (2026-09-13-0) `POST /api/git/commit` (`commitAll` in `gitcommit.go`) re-checks dirtiness (422 when clean or not a repo), then primes a repo-wide opencode session with `repoCommitPrompt()` mapped to the unassigned Discussions bucket; it reuses `commitStatus` from `lifecycle.go` via `GET /api/git/commit-status`, so the per-change and repo-wide flows share one poller.
- (2026-09-13-0) `Server.index` computes git state at render time for `indexView` (`GitRepo`/`GitDirty`), so the Commit all button is omitted when not a repo, disabled when clean, and enabled when dirty; the modal re-fetches `/api/git/status` on open and `commitAll` re-validates on confirm.
- (2026-09-13-0) `docswatch.go` skips attribute-only events (`ev.Op&^ fsnotify.Chmod == 0`): render-time git scans read modified files, and macOS surfaces those atime updates as `CHMOD`, which would otherwise spam docs events on every page load.
- (2026-09-13-1) `tuiconfig.go` builds `.lessmess/xdg/opencode/cli.json` per spawn (`ensureTUIConfig`) by merging the user's `cli.json` under forced `tabs.enabled=false` / `session.sidebar=hide`; `xdgEnv` replaces any inherited `XDG_CONFIG_HOME`, and `terminalWS` calls `SpawnWithEnv` with that env, falling back to nil (inherit) with a warning if generation fails.
- (2026-09-13-1) The TUI merge is best-effort and fail-open: a strict-JSON user config is merged, a JSONC one gets a conservative comment/trailing-comma strip, and anything still unparseable degrades to an overrides-only config rather than blocking the terminal; writes are atomic (`model.WriteFileAtomic`) and stay under `.lessmess/`.
- (2026-09-13-1) The generated TUI config is tooling state read only by the spawned opencode child; the server's own environment and the user's real `cli.json` are never modified.
- (2026-09-13-1) The embedded-terminal task panel is purely client-side (a mirror of the board DOM); the server surface for embedded terminals remains `terminalWS` plus `ensureTUIConfig`, with no new endpoint.
- (manual) `settings.go` owns the layered settings schema and stateless load/merge (`loadEffectiveSettings`, `mergeSettings`, `applySettingsPatch`): the project layer is root `lessmess.json`, the personal layer is `.lessmess/settings.json`, and each field is tri-state so unset inherits down to built-in defaults.
- (manual) `settingsapi.go` serves `GET /settings` (page), `GET/PUT /api/settings` (effective view plus both raw layers and per-field `sources`), and `GET /api/settings/options`; PUT validates a non-empty session agent/model against the live opencode service (`ListAgentsFor`/`ListModelsFor`) with 422 on unknown names, skipping validation when the service is unreachable.
- (manual) Settings wire into behavior via `Server.spawnSession` (agent/model defaults with a 400 retry that drops them), `Server.promptWith`/`promptAddendumFor` (appended to unmodified base prompts), the default branch recorded on new changes, and gates for `autoOpenTerminal`, `showArchived`, and `autoGardenerOnClose`.
- (manual) `settingschange.go` serves `POST /api/settings/change` (route in `server.go`): the Settings page's per-field Change button spawns a fresh discussion through the normal `spawnSession` flow, primed with a context block naming the field, its effective value, and its source, and maps it to the unassigned Discussions bucket.
- (manual) One settings-initiated discussion is active at a time: its session id lives in `.lessmess/settings-change.json` (missing or corrupt reads as "none"), and it is reused with a fold-in message until its bound change is Done/Cancelled or the session is gone.
- (manual) `settingsFieldValue` is the dotted-path allowlist mapping `/api/settings/change` fields to effective values — extend it in lockstep with `EffectiveSettings` when adding a setting, or the new field returns 422.
- (2026-09-13-2) Why save-time validation exists: the live service accepts unknown agent/model values at creation without error (the session then never runs), so the spawn-time 400 fallback can never catch a typo — `settingsapi.go` rejects unknown names at save with 422, validating against `ListAgentsFor`/`ListModelsFor` scoped to `s.st.Dir` and filtering agents to primary and non-hidden.
- (2026-09-13-2) `SetOpencode` also wires a `spawn` closure into `gardenerRunner` so configured agent/model defaults apply to docs jobs, and the runner appends its own gardener addendum (`promptAddendumFor(r.root, "gardener")` in `docssession.go`) because it has no `Server` access; the other session-creating flows append their addenda at the call site via `Server.promptWith`.
- (manual) Setup mode: when the repo has no `changes/` tree, `cmd/lessmess` builds `SetupServer` (`setup.go`) instead of `Server`; `POST /api/setup/bootstrap` hot-opens the real store and swaps the root handler in-process, and `registerSetupRoutes` mounts the wizard page plus `/api/setup/*` on both muxes so the wizard stays reachable (Settings re-entry) after boot.
- (manual) Setup seams are package-level vars faked in tests: the `prereqProbe*` functions (`prereqs.go`, checks report ok/warn/fail and only `fail` blocks the wizard's continue gate — probes never auto-fix) and `newSeedSummarizer` (`setupseed.go`, one in-flight `docs.Seed` job per repo with in-memory progress lines for `/api/setup/docs-seed-status`).
- (manual) Onboarding state lives in `.lessmess/onboarding.json` (`onboarding.go`) and fails open: missing or malformed reads as incomplete, `Dismissed` hides the index finish-setup banner without completing, and the wizard's `/api/setup/complete` and `/api/setup/dismiss` endpoints write it.
- (2026-09-13-4) Setup mode is gated solely on `store.ErrNoChanges`, which covers both a missing `changes/` tree and a partial one (no root ledger); only a ledger that exists but fails to parse stays fatal. The setup mux serves the wizard page, static assets, the settings read/write/options handlers through a store-free `setupEnv`, and `/api/setup/*`; every other route is 503 (JSON) or a redirect (HTML).
- (2026-09-13-4) The wizard's exclusion-picker semantics live in `setup.go`: top-level picks become base-name patterns matching same-named dirs at any depth, nested picks become slash paths, `normalizeExcludes` drops redundant ancestors, and `updateConfigExcludes` replaces only picker-representable patterns while preserving hand-authored globs — shared by `POST /api/setup/bootstrap` and `POST /docs/exclusions` (422 on globs or escapes, 503 without a config).
- (2026-09-13-4) `docsseed.go` extends the setup seed job to the normal server (`POST /docs/seed`, `GET /docs/seed-status`, `GET/POST /docs/exclusions`): non-force runs target only dirs missing the doc pair via `docs.MissingDocDirs`, force redoes everything, and wizard, CLI, and server runs share one in-flight job registry plus the `.lessmess/docs-seed.json` cursor so they continue one another (409 while running, 503 without opencode or coverage).
- (2026-09-13-4) Onboarding surfaces on the normal server: `indexView.OnboardingPending` drives the dismissible finish-setup banner, `registerSetupRoutes` keeps `GET /setup` reachable for Settings re-entry, and `layout.html` skips the app chrome when `.Page` is `setup`.
- (2026-09-13-5) `coveredAncestors` (`touched.go`) adds every covered ancestor of the touched dirs — the root included, purely lexical so deleted paths still bubble — to close-out jobs via `DocsJob.Ancestors`; ancestors are full cage targets (snapshot/verify/restore) alongside the update dirs, while manual jobs stay single-section.
- (2026-09-13-5) `gardenerPrompt` (`docssession.go`) renders two sections for change jobs: update dirs keep the preserve wording; review-and-fix (ancestor) dirs may fix or delete learnings the change invalidated, and the reply must account for every removal or edit. The job-done log line carries the ancestors and the spawn closure logs the resolved model (`gardener session model`).
- (2026-09-13-5) `POST /docs/refresh` (`docsqueue.go`) unions queue-stale, hash-stale, and lint-flagged dirs (`docs.StaleLearningRefs`), chunking the union into ≤10-dir jobs (`docsJobMaxDirs`); each chunk's `LintRefs` lists exactly the flagged references its prompt names, so one fragile giant session can no longer flag everything stale at once.
- (2026-09-13-5) `GardenerModel` (`settings.go`) resolves the docs-job model chain `docs.gardenerModel` → `session.model` → service default; the gardener spawn closure passes it via `spawnSessionWithModel` (same 400-retry fallback), save-time validation 422s unknown models, and it applies to all queue-driven docs jobs — seed paths keep session defaults.
- (2026-09-14-1) `discussionPrompt` (`changesession.go`) opens with a step-0 empty-state rule: a bare prime — nothing appended below it — must not read `changes/` or summarize anything, replying with a one-line invite and stopping, and it explicitly claims precedence over every other instruction "including any appended addendum" until the user's first message. Index-page discussions therefore wait for the request, while the Settings Change flow still engages immediately because `settingschange.go` appends its context block below the base prompt (inside the "nothing below it" gate).
- (2026-09-14-1) The discussion prompt is pinned by tests: `TestDiscussionSession` asserts "plan a NEW change", "Empty state", "do NOT investigate the repository", and `What would you like to build?`; `settingswiring_test.go`/`settingschange_test.go` guard the older phrasings ("planning assistant", "DO NOT modify the repository", "EXPLICITLY agrees", "task-ID prefix", "Ask questions; help them decide") and the exact scaffold `curl` line. Keep all of those when rewording, and remember prompts are sent only at creation — existing sessions keep their original prime.
- (2026-09-14-1) `scaffoldChange`'s `changes/` writes are load-bearing beyond the store: they emit the SSE `fs`/`write` events the index page uses to follow the open discussion to its new board (terminal persistence, client-side in `app.js`). The DSC-02 fix deliberately added no server surface — don't gate or drop SSE events for scaffold writes.
