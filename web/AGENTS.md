# web

<!-- tasktracker:begin -->
- Purpose: Go package holding the lessmess web UI's embedded assets — `templates/` (html/template sources) and `static/` (CSS, JS, vendored htmx, Sortable, and xterm libraries; see `static/VENDOR.md` before updating them). `web.go` is the whole package: `FS embed.FS` via `//go:embed templates static` — new files under those trees are picked up automatically, but a new top-level path must be added to the embed list, and files must exist at build time.
- Root `agentsdocs.json` excludes only `web/static`, so all JS/CSS behavior described here sits outside docs coverage while `templates/` stays covered. `layout.html` parses with each page template into per-page template sets (`renderer.settings` and `renderer.setup` are separate from the board/index set), all sharing the `content` template; conventions live in `templates/AGENTS.md`.
- Index SSE refresh rules: `scheduleRefresh` full-reloads on `changes/` events, but never while a terminal overlay is open with a live session — `followSession()` polls and navigates to the board once the discussion scaffolds, so the same terminal reconnects. Background writes leave the change list stale by design while the terminal is open (boards are immune — they refresh via htmx fragment swaps), and `closeTerminal()` fires one deferred `scheduleRefresh()` to catch up.
- The shared header is a sticky `Changes`/`Explorer` topnav (52px, z-index 20) whose `.active` state is applied server-side from `pageData.Page`, under the z-index ladder header 20 < modals 25 < terminal overlay 30 < board detail panel 40 — keep new fixed/sticky surfaces inside that ladder. Brand icons load from the server-rendered dynamic routes; the static orange files under `static/` are only direct-`/static/` fallbacks.
- The detail modal navigates in-modal, entirely client-side: `buildDetailTOC()` fills the `.modal-toc` rail from h2/h3 ids (hidden under 2 headings, toggles `has-toc` which widens the modal), an rAF-throttled scroll-spy runs on `.modal-body`, and a delegated click handler keeps relative `.md` links in-modal by mapping them against the modal's `data-doc` context (`plan.md`, `(../)ledger.md`, nested `tasks/...` files, cross-change plans) — keep that mapping exhaustive when adding nested link shapes.
- The index table is sortable client-side (`initIndexSort`): header clicks sort rows from `data-*` attributes (`data-tasks`/`data-status-rank` numeric, `data-updated` string, cell text otherwise), toggle `sort-asc`/`sort-desc` plus `aria-sort`, and persist `{col, dir}` to localStorage `tt-index-sort`, re-applied on every load; corrupt stored values fail open to the server's newest-first default.
- The explorer's client behavior: a `docs` SSE listener refreshes `#explorer-tree` and restores open nodes, selection is tracked client-side with `#explorer-detail` re-fetched per directory, tree fragments injected via `innerHTML` must pass through `htmx.process`, and the `.explorer-chat` handler runs in the capture phase from the detail header.
- The docs bell and findings modal are client-rendered by `checkValidation` (findings cached, banner is violations-only, badge re-renders on `tt:docs-event`); the modal's refresh button posts `/docs/refresh` and its seed button relabels "Run missing docs (N)" from `/api/validate`'s `docsSeedPending` — both disable while running and re-enable on the next docs SSE event.
- The embedded terminal overlay (`openTerminal`) connects to any session via `opencode2 --session <id>`; the task panel beside it (`syncTerminalTasks`) mirrors the `#board` DOM into `#terminal-tasks`, re-syncs from the board's `htmx:afterSwap`, and its rows reuse each card's own `hx-get` targeting `#detail` — which stacks above the overlay, so the global Escape handler closes a visible `#detail` first.
- The settings editor contract: `initSettings` finds every hook (`#settings-page`, scope radios, `.settings-nav` + `data-group`, `data-field`/`data-kind`/`[data-input]`, section `[data-save]`, source badges, datalists) — reshape `settings.html`/`app.css` freely but keep those hooks; the display-only `general` section carries no fields or `[data-save]`; agent/model inputs are `<datalist>` comboboxes that stay free text so settings remain editable offline.
- The setup wizard's client logic (`initSetup`) gates Continue on `ready` (only `fail` prereqs block), POSTs bootstrap `{docsCoverage, excludeDirs}` (re-submitting updates an existing `agentsdocs.json`), treats docs seeding as opt-in with `/api/setup/docs-seed-status` polling, and uses an exclusion picker whose semantics (top-level = base-name patterns pruning subtrees, nested = exact paths) are shared with the Settings `#docs-exclusions` editor via `POST /docs/exclusions`.
- Theming follows the accent: the `--accent`/`--accent-hover` pair arrives via the server-injected inline `<style>` (`{{.AccentStyle}}`, palette from `internal/server/accent.go`) and derivatives `color-mix` from `var(--accent)` — the only sanctioned hex literals are the theme-block fallback definitions of `--accent` and the xterm cursor's legacy fallback. The Settings accent picker is the `data-kind="accent"` field: swatch chips built from `/api/settings/options`, a pending pick kept on the container's `data-value` behind the `accentTouched` guard (`render()` must not overwrite it mid-pick) and live-previewed by rewriting the head `#accent-style` element from the four hexes the options payload carries per entry; `syncAccentValues()` is the single reset point (initial load, scope switch, save success), `""` clears to Auto (Auto in both layers re-rolls server-side), and a `.accent-shadow-note` fires when the Project scope is shadowed by a Personal override.
- The Commit all flow (`initCommitAll`) fetches `/api/git/status`, renders merged porcelain rows with per-file `+/-` counts, posts `/api/git/commit` on confirm, and polls `/api/git/commit-status` until done.
- Subagent chips (`refreshSubs` → `renderSubs`, re-run on every board swap) attach sessions carrying `task` to the matching card, fall back to the `#board-subs` strip for `parent`-only sessions, and render dead subs (`live:false`) dimmed but openable via Talk → `openTerminal` — the board trusts the server's `task`/`parent` payload fields and never parses titles itself.
- Board interactions: `.card-expand` posts `/changes/{id}/expand`, card/title clicks drill into `?task=` sub-boards with breadcrumbs (add-task posts `parent`, sub-board Continue keys `tt-last-session:<change>/<task>`); the `#overall-status` select (rendered only for Planned/In progress/Blocked) POSTs `/changes/{id}/status` then `location.reload()` even on failure so the pill repaints from server truth; the close-change confirm intentionally still warns while `Test` tasks remain.
