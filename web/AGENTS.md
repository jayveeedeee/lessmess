# web

<!-- tasktracker:begin -->
- Purpose: Go package holding the lessmess web UI's embedded assets — `templates/` (html/template sources) and `static/` (CSS, JS, vendored htmx, Sortable, and xterm libraries; see `static/VENDOR.md` before updating them). `web.go` is the whole package: `FS embed.FS` via `//go:embed templates static` — new files under those trees are picked up automatically, but a new top-level path must be added to the embed list, and files must exist at build time.
- Root `agentsdocs.json` excludes only `web/static`, so all JS/CSS behavior described here sits outside docs coverage while `templates/` stays covered. `layout.html` parses with each page template into per-page template sets (`renderer.settings` and `renderer.setup` are separate from the board/index set), all sharing the `content` template; conventions live in `templates/AGENTS.md`.
- Index SSE refresh rules: `scheduleRefresh` full-reloads on `changes/` events, but never while a terminal overlay is open with a live session — `followSession()` polls and navigates to the board once the discussion scaffolds, so the same terminal reconnects. Background writes leave the change list stale by design while the terminal is open (boards are immune — they refresh via htmx fragment swaps), and `closeTerminal()` fires one deferred `scheduleRefresh()` to catch up.
- The shared header is a sticky `Changes`/`Explorer` topnav (52px, z-index 20) whose `.active` state is applied server-side from `pageData.Page`, under the z-index ladder header 20 < modals 25 < terminal overlay 30 < board detail panel 40 — keep new fixed/sticky surfaces inside that ladder. The header Chat button (`#chat-btn`, inside the setup guard) is wired in the shared init path so it works on every page: it POSTs `/chat/session` (disabled while pending, server error alerted) and opens the fresh session with `openChat` — the Chat overlay, not `openTerminal`, and a deliberate open that never gates on the `session.autoOpenTerminal` setting, matching the explorer chat. Brand icons load from the server-rendered dynamic routes; the static orange files under `static/` are only direct-`/static/` fallbacks.
- The detail modal navigates in-modal, entirely client-side: `buildDetailTOC()` fills the `.modal-toc` rail from h2/h3 ids (hidden under 2 headings, toggles `has-toc` which widens the modal), an rAF-throttled scroll-spy runs on `.modal-body`, and a delegated click handler keeps relative `.md` links in-modal by mapping them against the modal's `data-doc` context (`plan.md`, `(../)ledger.md`, nested `tasks/...` files, cross-change plans) — keep that mapping exhaustive when adding nested link shapes.
- The index table is sortable client-side (`initIndexSort`): header clicks sort rows from `data-*` attributes (`data-tasks` — the server-computed recursive task count, rendered `x/y` — and `data-status-rank` numeric, `data-updated` string, cell text otherwise), toggle `sort-asc`/`sort-desc` plus `aria-sort`, and persist `{col, dir}` to localStorage `tt-index-sort`, re-applied on every load; corrupt stored values fail open to the server's newest-first default.
- The explorer's client behavior: a `docs` SSE listener refreshes `#explorer-tree` and restores open nodes, selection is tracked client-side with `#explorer-detail` re-fetched per directory, tree fragments injected via `innerHTML` must pass through `htmx.process`, and the `.explorer-chat` handler runs in the capture phase from the detail header.
- The docs bell and findings modal are client-rendered by `checkValidation` (findings cached, banner is violations-only, badge re-renders on `tt:docs-event`); the modal's refresh button posts `/docs/refresh` and its seed button relabels "Run missing docs (N)" from `/api/validate`'s `docsSeedPending` — both disable while running and re-enable on the next docs SSE event.
- The embedded terminal overlay (`openTerminal`) connects to any session over a WebSocket at `/terminal/ws?session=<id>`; the task panel beside it (`syncTerminalTasks`) mirrors the `#board` DOM into `#terminal-tasks`, re-syncs from the board's `htmx:afterSwap`, and its rows reuse each card's own `hx-get` targeting `#detail` — which stacks above the overlay, so the global Escape handler closes a visible `#detail` first.
- The settings editor contract: `initSettings` finds every hook (`#settings-page`, scope radios, `.settings-nav` + `data-group`, `data-field`/`data-kind`/`[data-input]`, section `[data-save]`, source badges, datalists, `#opencode-default-note`/`#opencode-default-text` with the `#align-default-agent` button) — reshape `settings.html`/`app.css` freely but keep those hooks; the `general` section carries the project-name string field and `[data-save]`, and a successful general save reloads the page so the server-rendered brand and tab title pick up the new name; the divergence note unhides only when `view.opencodeDefaultAgent.declared` differs from the effective `session.agent`, and its Align button POSTs `/api/settings/opencode-default-agent` then reloads the settings view; agent/model inputs are `<datalist>` comboboxes that stay free text so settings remain editable offline.
- The setup wizard's client logic (`initSetup`) gates Continue on `ready` (only `fail` prereqs block), prefills the name step's `#setup-project-name` from `GET /api/settings`'s effective value (its Save PUTs `{general:{projectName}}`; Skip continues unsaved), POSTs bootstrap `{docsCoverage, excludeDirs}` (re-submitting updates an existing `agentsdocs.json`), treats docs seeding as opt-in with `/api/setup/docs-seed-status` polling, and uses an exclusion picker whose semantics (top-level = base-name patterns pruning subtrees, nested = exact paths) are shared with the Settings `#docs-exclusions` editor via `POST /docs/exclusions`.
- Theming follows the accent: the `--accent`/`--accent-hover` pair arrives via the server-injected inline `<style>` (`{{.AccentStyle}}`, palette from `internal/server/accent.go`) and derivatives `color-mix` from `var(--accent)` — the only sanctioned hex literals are the theme-block fallback definitions of `--accent` and the xterm cursor's legacy fallback. The Settings accent picker is the `data-kind="accent"` field: swatch chips built from `/api/settings/options`, a pending pick kept on the container's `data-value` behind the `accentTouched` guard (`render()` must not overwrite it mid-pick) and live-previewed by rewriting the head `#accent-style` element from the four hexes the options payload carries per entry; `syncAccentValues()` is the single reset point (initial load, scope switch, save success), `""` clears to Auto (Auto in both layers re-rolls server-side), and a `.accent-shadow-note` fires when the Project scope is shadowed by a Personal override.
- The Commit all flow (`initCommitAll`) fetches `/api/git/status`, renders merged porcelain rows with per-file `+/-` counts, posts `/api/git/commit` on confirm, and polls `/api/git/commit-status` until done.
- Subagent chips (`refreshSubs` → `renderSubs`, re-run on every board swap) attach sessions carrying `task` to the matching card, fall back to the `#board-subs` strip for `parent`-only sessions, and render dead subs (`live:false`) dimmed but openable through their Chat (`openChat`) and Terminal (`openTerminal`) buttons — the board trusts the server's `task`/`parent` payload fields and never parses titles itself.
- Board interactions: `.card-expand[data-expand]` buttons on leaf cards post `/changes/{id}/expand` (an already-exists 409 still lands there) and navigate to the task's sub-board, container cards instead drill into `?task=` sub-boards through their rollup badge link (`x/y ✓`), and card titles open the nested task detail in-modal — `refreshBoard()` re-requests `location.pathname + location.search`, so SSE fragment swaps keep the drill-down scope — sub-boards render breadcrumbs and scope the sessions panel and Continue button to the exact task (Continue keys `tt-last-session:<change>/<task>`, the panel filters sessions to `task === boardTask()`, and its New session button POSTs that task so the session binds at that level; the board has no task-creation form — tasks are created in sessions or via the API); the close-change confirm warns while any task is not Done or Cancelled (`countOpenTasks()` counts only the visible board — recursive readiness is the server's gate) before posting the lifecycle action. The sessions panel's Spawn change flow (`initSpawnChange`) reloads the `handoff*.md` picker from `GET /changes/{id}/handoffs` on every open, POSTs `/changes/{id}/spawn-change` (title, prefix, artifact), surfaces server error messages in `#spawn-error`, opens the spawned session via `openPreferredSession` (Terminal, or Chat on narrow viewports), and badges `#sessions-list` rows `from <change>` from the payload's `spawnedFrom`.
