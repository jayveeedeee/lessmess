# web/templates

<!-- tasktracker:begin -->
- Purpose: Go `html/template` sources for the lessmess web UI; each file defines named templates rather than serving standalone pages. `layout.html` is the base shell rendering the `content` template; `partials.html` holds shared fragments (`boardFragment`, `taskDetail`, `planDetail`, `ledgerDetail`, `banner`) for htmx-swapped responses. Server data lives under `.Data`, htmx attributes drive interactivity, and custom funcs (`statusClass`, `base`, `markdown`, `statusRank`) are registered by the Go renderer. Template names are parsed into one global set — keep `define` names unique across files — and when an edit looks unapplied in the running UI, restart the server before concluding anything (a stale process serves old HTML).
- `index.html` exposes only the opencode-driven "New change session" form (`hx-post="/changes/session"`); the plain "New change" form is gone from the UI (`POST /changes` remains for API clients — do not resurrect the form without a decision). The Discussions list is client-rendered by `app.js`. The Commit all button (`#commit-all-btn`, state from `.Data.GitRepo`/`.Data.GitDirty`) and the `#commit-modal` ids (`commit-file-list`, `commit-stat`, `commit-confirm-btn`, `commit-modal-status`) are wired by id — keep them stable. The `#spawn-fallback-banner` (`.banner.warn`, above the table) is purely server-rendered — present only when `.Data.SpawnFallback` is non-nil, sentence from `SpawnFallback.Summary` plus a Review settings link — so its markup is absent otherwise and render tests can assert both states.
- `board.html` carries the lifecycle and session controls (`commit-btn`, `close-change-btn`, `reopen-btn`, `sessions-btn`, `new-session-btn`) and the Continue-session button whose label `app.js` flips; the drill-down rendering (`.crumbs` from `.Data.Crumbs`, rollup badges, `.card-expand[data-expand]`, parent-aware add-task form) plus `#board[data-task]` and modal `data-doc` are load-bearing — the terminal task panel mirrors `#board`/`.cards[data-status]`/`.card[data-task]` and render tests assert them.
- `layout.html`'s header is `brand | topnav (Changes, Explorer) | topnav-right (Settings) | #notif-bell | #theme-toggle`, with `.active` applied from `.Page` comparisons; the `brand` anchor renders `<span class="brand-name">{{.ProjectName}}</span>` beside the icon, and the terminal `.terminal-head` mirrors the same span before `#terminal-title`. The docs bell (`#notif-bell`, `#notif-badge`) opens `#notif-modal` (`#notif-list`, `#docs-refresh-btn`, `#docs-seed-btn`, `#docs-seed-force` + label, `#notif-refresh-status`) — all wired by id in `app.js`. The shared `banner` partial renders only for `changes/` violations.
- `layout.html` also owns the terminal overlay (`.terminal-body` flex row with `#terminal-container` plus the hidden `#terminal-tasks` aside — keep the id and `hidden` default so unassigned terminals stay full-width) and renders the setup page chrome-free via `{{if ne .Page "setup"}}` guarding the topnavs, bell, and banner: any new global header element must respect that conditional. Vendored htmx/Sortable/xterm stay at pinned `?v=1`; only `app.css`/`app.js` use the content-hashed `.AssetsV`.
- `layout.html`'s `<head>` emits `{{.AccentStyle}}` — the server-rendered inline `<style>` (id `accent-style`) setting `--accent`/`--accent-hover` for `:root` and `[data-theme="light"]` — so templates never hardcode palette colors; keep the emission intact, since `app.js`'s accent picker live-previews by rewriting that element's text. Brand `<link>`s and `.brand-icon` `<img>`s point at the dynamic accent-rendered routes (`/icon.svg`, `/favicon.ico`, `/apple-touch-icon.png`), not static files. The `<title>` is exactly `{{.ProjectName}}` on every page — per-page `pageData.Title` is still populated by call sites but no longer feeds the title element.
- `explorer.html` defines `content`, the dirs-only `explorerTree`/`explorerNode` fragments, and `explorerDetail`: a split shell where each `<summary>` carries `hx-get="/explorer/detail?dir={{.Rel}}"` targeting `#explorer-detail`, every `<details>` keeps `data-rel` so refreshes restore open nodes, and the recursive `{{template "explorerNode" .}}` reference must stay intact. Templates read `.Data.Enabled`/`.Root`/`.Dirs`/`.Files`/`.Purpose`/`.Blurb` from the view models in `internal/server/explorer.go`; a missing purpose renders the placeholder.
- `taskDetail`, `planDetail`, and `ledgerDetail` share one modal shape: `.modal-head`, then `.modal-panes` holding an empty `<nav class="modal-toc" hidden>` (`app.js` populates it — it must stay present in all three) and `.modal-body.prose` rendered with `{{markdown .Body}}`. `ledgerDetail` shows raw `ledger.md` with its leading H1 dropped server-side (`dropLeadingH1`).
- `index.html`'s six data `<th>`s wrap `button.sort-btn[data-sort-col]` with a `span.sort-ind`, and each body `<tr>` carries `data-tasks`, `data-status-rank` (`{{.Status | statusRank}}`), and `data-updated` — keep the attribute names and the `statusRank` pipe intact, since `app.js` sorts on them and `render_test.go` asserts them.
- `settings.html` (parsed into its own `renderer.settings` set) is scope strip → split → footer with six `.settings-section[data-section]` blocks (general, session, prompts, git, ui, docs) whose `data-section`/`data-group` values double as `lessmess.json` keys and `initSettings` PUT payload keys — rename them in template, nav, and JS together. The `.scope-seg` labels are exactly `Personal`/`Project` over visually hidden `input[name="settings-scope"]` radios (values `project`/`personal`) that must stay for `initSettings` and `render_test.go`; the layer-explanation strings in `settings-foot` are test-asserted too.
- `settings.html` hooks are addressed by id — `#settings-page`, `#settings-load-error`, `#settings-options-hint`, `#settings-agent-list`, `#settings-model-list`, `.src-badge`, `.settings-status`, `#opencode-default-note` with `#opencode-default-text` and its `#align-default-agent` button — and fields expose `data-field`/`data-kind` plus `[data-input]`. The `session.agent` field carries that divergence note: a `hidden` `.banner.warn` shipped empty, which `app.js` fills from `view.opencodeDefaultAgent` and unhides (note and Align button) only when the declared `default_agent` differs from the effective `session.agent`. The `general` block is a real editable section: the Project name string field (`data-field="general.projectName"`, `data-kind="string"`) with source badge, ✦ change button, and a section `[data-save]`; an empty input means the folder default (placeholder/fallback from `view.defaultProjectName`), a successful general save reloads the page so the server-rendered brand and tab title pick up the name, and the wizard re-run is a plain link below the field; the docs section holds the `docs.gardenerModel` datalist input and the `#docs-exclusions` widget; the ui section's Accent field (`data-field="ui.accent"`, `data-kind="accent"`) is an initially empty `<div class="accent-swatches" data-value="">` that `app.js` fills, beside a `hidden` `.accent-shadow-note` paragraph `app.js` unmasks when a Personal override shadows the Project scope.
- `setup.html` (parsed into its own `renderer.setup` set) defines `content` for the six-step wizard: `data-step` sections `prereqs`, `name`, `bootstrap`, `agent`, `docs`, `finish` with matching `data-step-nav` items, and inner controls (`#setup-prereq-list`, `#setup-recheck-btn`, `#setup-project-name`, `setup-name-scope` radios with Project checked, `#setup-name-save`/`#setup-name-skip` + `#setup-name-status`, `#setup-exclude-list`, seed progress, step buttons) that are all `initSetup` DOM hooks — renames move template and `app.js` together. `GET /setup` renders it even on fully initialized repos.
