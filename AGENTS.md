# Repository Agent Instructions

This repository uses **lessmess** for change management.

- Workflow state (changes, tasks, statuses, dependencies, decision logs) is tool-owned JSON under `.lessmess/workflow/` — committed, but **never edit it by hand**. Alter state only through the API endpoints or the board; `lessmess validate` checks the contract.
- Narrative documents — `changes/<id>/plan.md` and task prose under `changes/<id>/tasks/` — are markdown and edited directly.
- Change work happens in board-spawned sessions: their prime messages carry the current workflow instructions, deterministically selected and injected by the server from its embedded instruction modules (`GET /workflow/instructions` lists them).
- Do not scaffold changes yourself: discuss with the user and use the scaffold endpoint a session prime provides.

The sections below the markers are machine-maintained repository knowledge (doc pairs), refreshed by the doc gardener.

## Learnings

- Root holds only entry points and docs: `cmd/` the CLI, `internal/` the packages, `web/` the embedded assets; `changes/` is the canonical workflow tree and `.lessmess/` is gitignored tooling state; root PNGs (`ui.png` committed; `overlap.png`, `mine.png` gitignored) are ad-hoc screenshots, not build inputs, and `.gitignore` anchors the binary ignore to the root (`/lessmess`) so `cmd/lessmess/` source stays tracked. `README.md` is the human-facing overview of the CLI, board, and docs system — update it when user-visible commands, endpoints, or workflows change.
- Build with `CGO_ENABLED=0 go build -o lessmess ./cmd/lessmess`; verify with `go vet ./... && go test ./...`; check workflow data with `lessmess validate`. The root `lessmess` entry is gitignored build output, not a source directory.
- The web UI is embedded at build time (`//go:embed templates static` in `web/web.go`, served via `internal/server/render.go`), so template and static-asset changes are invisible in the running server until the binary is rebuilt and restarted.
- Every session opens in Chat — it is the sole session interface at every viewport width, and lessmess embeds no terminal: there is no PTY bridge, terminal WebSocket route, vendored xterm asset, or `internal/terminal` package, and shell/tool output appears only as rendered transcript content. The surface stays hand-written templates plus vanilla JS/CSS in `web/` — no client framework, no Node build step.
- The browser never talks to the OpenCode service directly: Chat calls explicit `/api/sessions/{sessionID}/chat*` routes (`internal/server/chat.go`) that authenticate server-side, so credentials never appear in browser responses or JS and there is no generic pass-through. Transcript freshness is a full snapshot on open/reconnect plus polling while the view is visible — deliberately no event-stream subsystem for chat (`/events` SSE is board/docs updates only) — and `internal/opencode` models only the stable fields lessmess renders, keeping `json.RawMessage` at message-part unions so unknown future parts decode and render as safe fallbacks instead of breaking the transcript.
- CLI subcommands are `serve`, `validate`, `migrate`, `init`, and `docs seed`; `--dir` selects the repository root and one process serves one repository. The module is `lessmess` (renamed from tasktracker): binary at `cmd/lessmess`, tooling state under `.lessmess/`, while the doc-marker syntax (`tasktracker:begin`/`tasktracker:end`), `tt-` frontend prefixes, and the repository folder name are unchanged. Legacy state converts one-way to the JSON store: `serve` and `validate` run `store.MigrateIfNeeded` automatically before the store opens, the `migrate` subcommand does it on demand (`--dry-run` verifies without writing), and `store.MigrateStateDir` renames a legacy `.tasktracker/` to `.lessmess/` only when the new dir is absent (called by `serve`, `validate`, `migrate`, `docs seed`, and defensively in `server.New`).
- The docs subsystem is opt-in: a committed root `agentsdocs.json` sets coverage with include/exclude globs (`web/static` is the only exclusion; hidden dirs and `changes/` are never covered), and without that file everything docs-related no-ops.
- Each covered folder carries a doc pair: `STRUCTURE.md` (machine-owned map, regenerated wholesale inside its markers — only an em dash purpose cell may be hand-replaced with prose, and table cells must avoid pipes and newlines) and `AGENTS.md` (current-state learnings, machine-maintained inside the markers, at most 15 per file). The root workflow text above the markers is embedded at `internal/docs/assets/workflow_agents.md` (go:embed) and drift-pinned — update both together (`awk '/^<!-- tasktracker:begin/{exit} {print}' AGENTS.md > internal/docs/assets/workflow_agents.md`).
- `lessmess init` bootstraps a workflow-ready repo (workflow text, `changes/` skeleton, `.gitignore`, starter `opencode.json`, default `agentsdocs.json`) merge-safely and idempotently; `docs seed` generates first-pass doc pairs bottom-up and resumes via `.lessmess/docs-seed.json`.
- Closing a change enqueues serialized gardener jobs (`.lessmess/docs-queue.json`) chunked at 3 covered dirs — consecutive chunks of the touched set, each carrying its covered ancestors deduped against earlier chunks and budgeted 15 minutes base plus 5 minutes per target dir (fix/delete license, removals accounted in the reply); `POST /docs/refresh` unions queue-stale, hash-stale, and lint-flagged dirs into the same ≤3-dir chunks, where the stale-reference lint warns `learning cites missing path` (bell + `lessmess validate`, never an error) when a learning's backticked path resolves to nothing.
- `opencode.json` pre-approves unattended agent sessions with allow-all inside the project and denies for external directories, `.env` reads, and `git push`.
- Settings are layered (committed root `lessmess.json` = project policy, gitignored `.lessmess/settings.json` = personal override, defaults beneath), read statelessly on every use, and fail open when malformed; `general.projectName` — the brand name shown beside the logo and the browser tab title — computes its folder-basename default at read time and never persists it. `prompts.*` addenda append at session creation only (existing sessions keep their prime), and `docs.gardenerModel` overrides the model for queue-driven docs jobs.
- Tasks decompose recursively and only on user instruction: a decomposed task keeps its `changes/<id>/tasks/NN-slug.md` file and gains a sibling `NN-slug/` container holding its subtasks' prose, while the sub plan itself — dotted task IDs (`PREFIX-NN.MM`), statuses, priority order — is JSON state, `changes/<id>/tasks/NN-slug/ledger.md` links serve a generated view rather than a file, progress rollup is display-only, and agents propose decompositions but never create containers unprompted.
- `changes/` documents never record session IDs: session-to-change/task mappings live only in `.lessmess/sessions.json` tooling state.
- A session bound to a change spawns a genuinely new change only via the handoff: write `changes/<id>/handoff-<topic>.md`, then POST `/changes/{id}/spawn-change` with title, prefix, artifact, and the caller session — always with the user's explicit approval; `handoff*.md` files at a change root are workflow-legal supporting artifacts and validate clean, and scaffold still refuses bound sessions with a 409 that teaches this path.
- Session spawn de-escalates rather than dropping config: on a 400 the opencode create walks agent+model → agent-only → model-only → plain, the fallback is recorded in `.lessmess/spawn-fallback.json` and shown as a board banner until the next clean spawn clears it, and the Settings Align button patches only `default_agent` in the served repository's `opencode.json` (order-preserving, JSONC refused) to match the effective `session.agent`.
